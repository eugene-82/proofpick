# ProofPick TASKS

이 폴더는 Codex가 ProofPick을 한 번에 전부 구현하지 않고,
작고 검증 가능한 작업 단위로 순차 개발하도록 하기 위한 작업 티켓 모음입니다.

## Codex에 시키는 기본 방식

예:

```text
AGENTS.md와 PROJECT_SPEC.md를 먼저 읽어라.
그 다음 TASKS/001-project-bootstrap.md만 구현해라.
작업 범위를 벗어나는 리팩터링이나 다음 TASK 구현은 하지 마라.
완료 후 변경 파일, 테스트 결과, 남은 이슈를 보고해라.
```

작업이 완료되고 테스트가 통과하면 다음 TASK로 진행합니다.

## 권장 순서

001 → 002 → 003 → ... → 020

단, 실제 개발 상황에 따라 서로 독립적인 작업은 병렬 진행할 수 있지만
API/DB/AI 계약을 임의로 바꾸지 않아야 합니다.

## 핵심 원칙

- `PROJECT_SPEC.md`가 구현의 주 명세
- `AGENTS.md`가 Codex 운영 규칙
- `TASKS/*.md`가 현재 작업 범위
- 한 작업에서 관련 없는 기능을 같이 구현하지 않기
- 테스트 실패 상태에서 다음 작업으로 넘어가지 않기
- 강한 모델은 불확실할 때만 사용
- 원문은 한 번 압축하고 구조화된 Evidence를 재사용
- 대안 제품도 반드시 동일 기준으로 재검증
